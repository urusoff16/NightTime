# Smart Dark / AI Dark Mode — спецификация

Статус: утверждённая рабочая архитектура, реализация выполняется по этапам.  
Название в интерфейсе: **Умный режим**. Слово «AI» описывает локальный анализ, а не обязательный вызов LLM.

## Цель и границы

Улучшить текущую тему Dark Reader локальным анализом вычисленных стилей и реальной иерархии цветов. Уже тёмные или читаемые области не должны затемняться/перекрашиваться без необходимости. Приоритет — различимый текст на его фактическом фоне, визуальная иерархия профиля, сохранение акцентных оттенков и обратимое применение.

Первая версия — детерминированные алгоритмы в content script; сетевой AI, отправка текста/DOM страницы и новые внешние зависимости не нужны. Dark Reader остаётся базовым преобразователем широкого CSS. Smart Dark добавляет выборочную коррекцию тех текстовых элементов, чей контраст после базового преобразования недостаточен.

## Поток данных

```text
Content script каждого разрешённого frame
  → сбор ограниченной выборки видимых текстовых элементов
  → вычисленные стили и compositing цепочка
  → краткий PageColorReport и тип страницы
  → локальная классификация ролей и contrast pairs
  → минимальное преобразование OKLCH (в первую очередь L)
  → минимальная reversible foreground correction
  → пакетные обновления новых/изменённых узлов
  → полная очистка собственных атрибутов, observer и stylesheet

Dark Reader остаётся отдельным базовым слоем; background/service worker не
читает DOM. Закрытый Shadow DOM и недоступные frames остаются нетронутыми.
```

Реализация следует функциональному стилю проекта и находится под `src/engines/smart-dark/` либо в ближайшей принятой структуре `src/engines/`. Не создавать слой файлами-заглушками только ради перечисленных в исходном промпте названий.

## Данные и анализ

`ElementStyleSample` хранит только компактные значения: тип/семантические подсказки, видимость, площадь, цвет текста, фон, effective background, рамки, fill/stroke, размер/насыщенность шрифта, прозрачность и вид `background-image`. Не удерживать целый `CSSStyleDeclaration`, текст узла или HTML.

`PageColorReport` агрегирует светлоту и покрытие поверхностей, цветовые кластеры, пары «текст/фон», найденные CSS color variables, градиенты, число выборки и безопасно исправимые contrast issues. DOM-анализ выполняется в каждом разрешённом content script frame. Родитель не читает cross-origin iframe.

Первичный обход ограничен настраиваемым soft/hard budget: viewport и его предки, крупные поверхности, навигация, фиксированные области, формы и диалоги получают приоритет; невидимые/дальние узлы — пакетами в idle time. Для текста используется TreeWalker и дедупликация содержащих элементов; открытые shadowRoot обходятся рекурсивно с учётом повторного посещения.

CSS custom properties можно записывать в отчёт только когда значение успешно разобрано как цвет. Глобально переписывать неизвестные переменные нельзя. Когда безопасное scoped переопределение переменной не подтверждено, используется собственный stylesheet для отдельных текстовых целей.

### Effective background и альфа

Прозрачный фон элемента компонуется с фонами предков до первого достоверного непрозрачного источника. RGBA alpha и opacity элемента/предков учитываются отдельно по порядку compositing. Градиенты и изображения классифицируются, но пиксельный цвет из cross-origin изображения не извлекается. Неоднозначные поверхности пропускаются или получают только консервативную правку текста, когда контраст можно оценить надёжно.

Прозрачность предка нельзя отменить стилем дочернего текста. Первая версия не поднимает opacity целого контейнера с разнородным содержимым. Если нужный контраст при исходной альфе недостижим, отчёт помечает предел коррекции, а не выдаёт ложную гарантию.

## Цвет и интервенция

Цветовой путь — sRGB → linear RGB → OKLab/OKLCH → transform → sRGB. Близкие цвета кластеризуются детерминированно по светлоте/цветности/оттенку, частоте и площади. Роли определяются совокупностью HTML/ARIA, DOM-контекста, размера, повторяемости, цвета и контраста; классификацию не выводить из одного оттенка.

Уровни вмешательства:

0. Поверхность и текст уже читаемы — оставить как есть.
1. Исправить только недостаточно контрастный текст/акцент.
2. Также исправить различимость рамок и элементов управления.
3. Согласованно преобразовать выбранные поверхности смешанной страницы.
4. Применить полную базовую тёмную тему светлой страницы (существующий Dark Reader).

Smart Dark выбирает самый низкий уровень, который улучшает читаемость. Для обычного текста используется минимальный ориентир 4.5:1, для крупного — 3:1; настраиваемые цели не должны подменять стандарт обязательным правилом 7:1. `ensureContrast()` ищет минимальное изменение OKLCH Lightness, удерживая hue/chroma насколько позволяет gamut и заданная граница. Акцентные цвета не обесцвечивать и не превращать в неоновые.

Dark/light/mixed detection оценивает взвешенные реальные поверхности и текстовые пары по viewport sampling и выборке крупных блоков. `prefers-color-scheme` и `color-scheme` — вспомогательные признаки: значение `light dark` не является доказательством, что текущая отрисованная страница уже тёмная.

## Применение, производительность, восстановление

- Не запускать повторный полный анализ на каждую мутацию и не делать `getComputedStyle()` для всей страницы в каждом кадре.
- Наблюдатель собирает только добавленные/изменённые корни, дедуплицирует их, ждёт 50–150 мс, затем обрабатывает небольшими read/calculate/write batch-ами. Предусмотреть fallback без `requestIdleCallback` и защиту от собственных мутаций.
- Общие преобразования цветовых signatures кэшировать только пока актуальны исходные стили/версия движка; кэш DOM очищается при выключении.
- Предпочтителен один scoped stylesheet без inline-перезаписей. Проверка в Chromium выявила, что Dark Reader повторно анализирует/переписывает динамически добавленные CSS-правила, из-за чего вычисленный цвет не совпадал с реально отрисованным. Поэтому текущий первый слой использует ограниченный foreground inline override только на элементах, где анализ доказал низкий контраст (лимит 1500), сохраняет исходное значение и priority свойства `color` и полностью восстанавливает их при обновлении/выключении. Остальные свойства и структура сайта не меняются. Перед расширением этой стратегии нужна повторная проверка поведения Dark Reader.
- Marker страницы и исходный атрибут, если такой уже занят, сохраняются и восстанавливаются без затирания посторонних токенов.
- Профиль применяется от свежих computed styles после базового движка; повторное переключение не сдвигает цвет прежней темы ещё раз. После disable восстанавливаются исходные inline-значение/priority `color` и маркеры, отключаются observer и очереди; страница остаётся в исходном состоянии.
- Изображения, видео, canvas, фотографии, код, сложные SVG/логотипы, системные controls, disabled/selected/focus states не меняются общим фильтром. Простые SVG `currentColor` следуют за рассчитанным foreground.
- Fullscreen/top-layer (например, модальный `dialog`) не подчиняется обычному z-index документа; его читаемость анализируется отдельно и не считается равной слою под затемняющим overlay.

## Порядок этапов и текущий статус

Реализация следует 16 этапам исходного полного запроса, без одного большого рефакторинга:

1. Архитектура проекта и этот документ.
2. Чистое ядро цвета: parse, sRGB/OKLab/OKLCH, alpha blend, контраст, unit tests. **Реализовано; базовые тесты проходят.**
3. Сбор видимого текста, computed styles, visibility, фон предков, краткий отчёт. **Реализована начальная версия для текста и сплошных фонов; расширенный report и fixture-покрытие впереди.**
4. Фактическая классификация light/dark/mixed и оценка darknessScore. **Начальная классификация сплошных достоверных поверхностей реализована; viewport sampling и взвешивание крупных блоков впереди.**
5. Color clustering и семантические роли. **Начальная детерминированная кластеризация текста и достоверных фонов в OKLab добавлена в отчёт; расширенная классификация ролей и влияние кластеров на преобразование палитры впереди.**
6. Выбор Intervention Level.
7. Генератор согласованной палитры для поверхностей, текста, рамок, акцентов и ссылок.
8. Безопасное обнаружение и scoped overrides цветовых CSS variables.
9. Генерация/применение/восстановление темы.
10. Защита и поэтапная поддержка media, SVG, background images и gradients.
11. Incremental MutationScheduler для SPA и динамического DOM.
12. Style/color/effective-background cache и профилирование.
13. Опциональный компактный per-site profile без DOM/текста.
14. Локальный developer debug inspector.
15. HTML fixtures, Playwright rendered-style tests, profiling и ручная приёмка.
16. Лишь после стабильного core — рассмотрение необязательного AI Enhancement.

Сейчас внедряется безопасная начальная коррекция плохо читаемого текста поверх Dark Reader, после темы профиля и затемнения; это не означает готовность всех 16 этапов. Chromium E2E уже проверяет реальный contrast после каскада движков, SPA-like добавление/удаление текста и снятие исправления. Перед переходом к каждому следующему крупному этапу текущие lint, typecheck, unit tests, production build и доступные E2E должны оставаться зелёными.

На каждом этапе исправляются регрессии до продвижения дальше. Точные element budgets, пороги dark/light и performance timings принимаются по измерениям на контрольных страницах и хранятся в конфигурации, не объявляются универсальными константами.

## Интерфейс, приватность, отложенные функции

Умный режим не добавляет мелкие кнопки в popup. Popup сохраняет крупные основные действия и существующий выбор профиля; диагностика и, если понадобится, единственная настройка силы вмешательства размещаются в options.

По умолчанию анализ полностью локален. Per-domain cache хранит только hostname, версию алгоритма, тип страницы и пользовательские override; никогда DOM, HTML или текст. Инвалидация делается при изменении версии анализатора.

Отложены до работающего локального MVP: облачный/LLM AI enhancement и отдельный debug inspector UI. Gradient parser, безопасное преобразование простых SVG и инструменты разработчика добавляются после профилирования; для их отсутствия не имитировать полную поддержку.

## Критерии приёмки

- Тёмные и уже читаемые страницы остаются почти без изменений; серый малоконтрастный текст на тёмной поверхности улучшается локально.
- Контраст считается для composited текста/реального доступного фона с alpha и opacity предков.
- Hue читаемых ссылок/акцентов и относительная иерархия поверхностей сохраняются.
- Светлая страница получает Dark Reader; mixed page не превращается в сплошной одинаково чёрный слой.
- Переключение профиля рассчитывает результат заново без «прилипания» прежних цветов.
- SPA-мутации обрабатываются порционно без observer loop; анализ имеет soft/hard бюджеты и не сканирует всё на каждый кадр.
- Закрытый Shadow DOM и недоступные frames не читаются; доступные frame content scripts обрабатывают собственные документы.
- Выключение полностью восстанавливает затронутые цвета/маркеры и отключает observers/listeners.
- Изображения/видео/код/focus/disabled/semantic status визуально не ломаются.
- В первой версии нет внешнего AI, новых сетевых данных и новых runtime-зависимостей.
